**Education Researcher** is a fork of open-source BrainPilot focused on education research. New sessions default to **Education research**; choose **Neuroscience research** explicitly when you need the original domain. The domain setting changes prompts and available bundled resources. It does not erase knowledge already learned by the underlying model.

Run the education fork from [this repository's source](https://github.com/Kirihara-Ryouji/Education-Researcher). The published upstream `@brainpilot/app@0.2.3` package, official sandbox images, and hosted `brainpilot.chat` service do not contain this fork's education changes.

> **Research data:** start with fictional or de-identified examples. Follow your institution's ethics, authorization, consent, and data-management requirements for real student data. Do not send identifiable records or secrets to an external model without the required controls.

## 1. Run from source

Install **Node.js 22.13.0 or later** and npm. Clone the repository and enter the application root:

```bash
git clone https://github.com/Kirihara-Ryouji/Education-Researcher.git
cd Education-Researcher
npm ci
npm run build
npm run bp -- up
```

Open the local URL printed in the terminal. Press `Ctrl-C` to stop the foreground process. Keep the `--` separator when forwarding CLI arguments through `npm run`. See [Installation](./installation) for data directories and updates.

For a no-key interface smoke test, use mock mode. Its output cannot assess education research capability:

```bash title="macOS / Linux"
BP_MOCK=1 npm run bp -- up
```

```powershell title="PowerShell"
$env:BP_MOCK = '1'
npm run bp -- up
```

## 2. Connect a model provider

Real agent tasks need your own model provider. In **Settings → Providers → Add Provider**, enter a local name, API base URL, endpoint protocol, secret key, and exact model ID. Choose the protocol by the endpoint's actual format, not the model's name.

Select **Use** after saving to make it the default for new sessions, then **Test** to send a minimal real request. The test can consume a small amount of provider quota. Keep the key in local settings, not in chat, screenshots, or a repository. See [Providers](./providers) for protocols and configuration paths.

## 3. Run a first education research task

Select **New chat**, confirm **Education research (default)** as the research domain, and check the model. Start with a small task that a researcher can review:

> Draft a one-page study plan for whether formative feedback in middle-school mathematics improves students' problem-solving performance. Include the question, possible designs, intervention and outcome measures, confounders, ethics considerations, and evidence still to verify. Do not invent papers, effect sizes, or data.

State the study setting, method constraints, expected output, and decisions needing human review. Agent responses are research assistance; verify citations, measurement validity, statistical assumptions, and educational interpretation yourself. Use the [Research workspace](./research-workspace) to retain source, plan, and version history.

## 4. Hand off an accepted study plan

Under **Research projects**, create a project and study. Record the question, education level, course, institution, and uncertainties. Register sources and evidence, check original materials, then save and **accept the current plan**.

Use **Execution links → Hand off to education agent** to create a new education session. The workspace puts the accepted current plan and eligible cited publication excerpts into an **unsent draft**. It does not attach raw files, table rows, or participant records. Free-text fields may still contain personal information, so review the draft before sending. A handoff does not mean the model independently verified the sources.

## 5. Review the result

Inspect the **chat, files, agents, and trace** for the request, tool calls, saved artifacts, and evidence behind claims. Check at least:

- whether cited publications exist and their original text supports each claim;
- how samples, variables, measures, missingness, and exclusions were defined;
- whether saved files and code reproduce important numbers;
- whether the design supports causal statements and what needs human judgment.

The existing **Plugins → Datasets** catalog mainly contains neuroscience data. It is optional and is not loaded automatically into education sessions. See [Skills and Knowledge Base](./skills-knowledge-base) for the education skill set and the boundary around the local paper index.

## Common problems

| Symptom | First check |
| --- | --- |
| Startup fails | Node.js is at least 22.13.0, you are in the `Education-Researcher` repository root, and `npm ci` and `npm run build` completed |
| Port is occupied | Run `npm run bp -- up --port 9010` |
| Provider returns 401/403/404 | Check key, permissions, API root, protocol, and model ID |
| Mock output lacks research ability | Mock only checks the interface; configure and test a real provider |
| An old session still shows neuroscience | Unmarked historical sessions retain their original domain; create an education session |
| Workspace handoff is unavailable | Save and accept the **current** plan and check the model runtime |
| MCP tool is unavailable | Assign its server to Education research and start a new session |

See [Troubleshooting](./troubleshooting) for more diagnosis and the [education evaluation cases](https://github.com/Kirihara-Ryouji/Education-Researcher/blob/main/EDUCATION-EVALUATION.md) for human review criteria.
