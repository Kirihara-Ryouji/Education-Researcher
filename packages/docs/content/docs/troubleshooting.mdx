title: Troubleshooting
description: Diagnose source startup, research focus, model provider, and MCP issues in the education fork.
---

## Confirm you are running the education fork

Run Education Researcher from the repository root: complete `npm ci` and `npm run build`, then run `npm run bp -- up`. The upstream globally installed npm package and `brainpilot.chat` do not include this fork. If the education research option is missing, check that the browser is at the local address printed by this source process rather than an older process or hosted site.

New sessions default to education research; historical sessions without a domain marker retain neuroscience. The domain is fixed at session creation, so start a new session to switch. If a model still discusses neuroscience, check whether your prompt or attached materials contain that context, then inspect **Research focus** and domain-assigned MCP tools. The setting cannot erase the model's pretrained knowledge.

## Upstream package: `brainpilot: command not found`

Confirm the package is installed globally:

```bash
npm list -g @brainpilot/app --depth=0
```

If it is installed but the command is missing, check your npm global installation prefix:

```bash
npm prefix -g
```

On macOS/Linux, add the prefix's `bin` subdirectory to `PATH`; on Windows, add the prefix itself.

## Node Version Is Too Old

Education Researcher source requires Node.js 22.13.0 or later:

```bash
node -v
```

Install a newer Node.js release if the version is below `v22.13.0`.

## npm Global Permission Errors

If global install fails with permission errors, use a Node version manager or configure an npm user prefix. Avoid running npm with `sudo` unless you understand the security tradeoff.

## Port Already in Use

For the education fork, try another port:

```bash
npm run bp -- up --port 9010
```

The upstream globally installed package uses:

```bash
brainpilot up --port 9010
```

If you previously started BrainPilot in detached mode:

```bash
brainpilot status
brainpilot down
```

## Startup Works but the Browser Cannot Connect

Check the printed URL, then inspect logs:

```bash
brainpilot logs
```

If you are running in a remote machine or container, make sure the port is exposed and reachable from your browser.

## Provider Test Fails

Check:

- the API key is valid and not copied with extra spaces
- the base URL matches your provider's expected endpoint
- the selected protocol matches the provider
- the model ID exists, for example `glm-5.2`
- the machine can reach the provider network

After changing the active provider, start a new session if the existing one still uses old settings.

## MCP Server Does Not Show Tools

Check:

- the server name is unique and descriptive
- the transport matches the server: `stdio`, `http`, or `sse`
- the HTTP/SSE URL is reachable
- auth headers or query tokens are correct
- stdio command paths and arguments are valid
- the server's **Research focus** includes the current session; new servers default to education while old unmarked entries stay neuroscience-only

Create a new session after changing MCP settings.

## Clean No-key Smoke Run

Use mock mode to separate install problems from provider problems. The command below is for the upstream global package; use `BP_MOCK=1 npm run bp -- up --dir ./bp-smoke-test --port 9011` for this fork's source (set `$env:BP_MOCK = '1'` first in PowerShell). Mock output cannot assess education research quality.

```bash
BP_MOCK=1 brainpilot up --dir ./bp-smoke-test --port 9011
```

If mock mode works, focus on provider or MCP configuration.

## Dataset download failed

Use [Research datasets](./datasets) to check the selected download tools, access requirements, and retry flow. Tools must be installed on the machine running the backend. For an interrupted HTTP transfer, retain the `.part` file. A checksum-invalid file is preserved under a unique `.corrupt-…` name so the next retry can fetch fresh data. Check disk space before retaining large diagnostic copies.

If a completed dataset is missing files, reopen its details and rerun the same selection. Existing HTTP files are reused (and checked when a checksum is available); absent files can be fetched again. Provider-specific command downloads follow their tool's behavior.

## Local knowledge base is not ready

Uploading a PDF and preparing a searchable index are separate steps. Check **Settings → Knowledge Base** for missing environment/model setup, OCR or metadata credentials, and a failed indexing stage. The advanced log area shows technical details. Pausing log following does not stop an active build. See [Skills and Knowledge Base](./skills-knowledge-base).
