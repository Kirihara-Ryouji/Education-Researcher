## Install the education fork

**Education Researcher must be run from this repository's source.** Install Node.js 22.13.0 or later, then run these commands from the repository root:

```bash
git clone https://github.com/Kirihara-Ryouji/Education-Researcher.git
cd Education-Researcher
npm ci
npm run build
npm run bp -- up
```

Open the local URL printed in the terminal. New sessions default to education research; choose neuroscience explicitly in a new session when needed. The published upstream npm package, official container images, and hosted service do not include this fork's education changes. To update the source version, finish active work, stop the process, back up the data directory, pull the repository changes, rerun `npm ci` and `npm run build`, and restart with the same data directory.

## Upstream BrainPilot npm package

The following commands install the published upstream release for single-user local use. They do not install Education Researcher:

```bash
npm install -g @brainpilot/app@0.2.3
brainpilot up
```

The package includes the CLI, backend, runtime, web UI, and built-in skills needed for a local browser session.

## Update the upstream npm package and preserve your data

Finish or cancel active work and stop the old process before upgrading. For detached mode, pass the same data directory used when starting it:

```bash
brainpilot down --dir ./my-brainpilot-data
```

Back up that directory while the service is stopped. Also back up the detected knowledge-base root if it is outside the data directory. Then install the selected published version and restart using the same path:

```bash
npm install -g @brainpilot/app@latest
brainpilot --version
brainpilot up --dir ./my-brainpilot-data
```

For a reproducible upgrade, replace `latest` with the approved published version. Foreground users stop the old process with `Ctrl-C`. Verify saved conversations, provider configuration, persistent files, and download history after restart. Interrupted downloads require explicit retry; upgrading does not move your data automatically.

To return to a previous package version, stop the service, reinstall that known working version, and restart with the retained data directory. Do not delete data or overwrite a backup as part of a package rollback. Older versions may not display newer metadata.

## Uninstall the upstream npm package

```bash
npm uninstall -g @brainpilot/app
```

This removes the upstream CLI package. It does not delete your BrainPilot data directory. A source checkout needs no global-package uninstall; stop the process when finished.

## Data Directory

BrainPilot keeps its runtime files under one data directory. The resolution order is:

1. `--dir <path>`
2. `BP_DATA_DIR`
3. `./brainpilot` under the current working directory

Example:

```bash
brainpilot up --dir ./my-brainpilot-data
```

Typical contents:

```text
brainpilot/
  bp_template/
    providers.json
    mcp_servers.json
    settings.json
    skills/
  data/
    datasets/
      .jobs.json
  workspaces/
  .bp/
  .runtime/
```

## Local Isolation

The npm path is a local process. It does **not** create a Docker sandbox. Agents read and write under the session workspace inside the data directory, so choose that directory carefully and avoid pointing BrainPilot at private folders you do not want agents to inspect.

For stronger process isolation, use [Docker deployment](./docker) instead of the npm local
process.

## Run upstream BrainPilot from source

The following commands use the original BrainPilot source and do not include Education Researcher's changes:

```bash
git clone https://github.com/NeuroAIHub/BrainPilot.git
cd BrainPilot
npm install
npm run build
npm run bp -- up
```

For a no-key smoke run:

```bash
BP_MOCK=1 npm run bp -- up
```

With `npm run`, keep the `--` separator so flags are forwarded to the BrainPilot CLI.

## Detached Mode

The globally installed upstream BrainPilot can run in the background:

```bash
brainpilot up --detach
brainpilot status
brainpilot logs
brainpilot down
```

Use foreground mode while learning; use detached mode when you want it to keep running after the terminal command returns.
