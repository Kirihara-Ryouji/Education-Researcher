title: Research workspace

**Research projects** are the education fork's main starting point. They retain study definitions, materials, evidence, plan versions, execution links, table analysis, claims, and reports. These records help trace conclusions to inputs; they do not replace independent review of original sources and methods.

## Build a reviewable education study

1. Create a project and study. Record the question, purpose, education level, institution type, course or task, cultural and language context, time frame, and uncertainties. Save a new version and reason when the study definition changes.
2. Under **Sources and materials**, register publications, surveys, interviews, observations, datasets, or other materials, including provenance, citations, and access limits. Local PDF, DOCX, TXT, and MD file versions can be uploaded. Registering a source does not verify its content.
3. Locate passages in the original material and record evidence. Keep **Unverified**, **Source checked**, and **Content checked** distinct. Recheck locators after a file update or an unverified manual transcription.
4. Save a plan covering design, measurement, analysis, ethics, and limitations. After review, **accept the current version**. Recheck and revise the plan if the study definition or evidence changes.
5. Link execution, analysis, and claims to the accepted plan, then build a report version from accepted, currently reviewable claims. Keep the report version and citation manifest with any downloaded Markdown report.

## Hand off to an education agent

Use **Execution links → Hand off to education agent → Create education session**. The app creates a new session with an **unsent draft** containing the accepted current plan and up to 12 content-checked publication excerpts with citations. It does not automatically attach raw files, CSV rows, or participant records. The study question and plan remain free text: check them for identifiable student information and decide whether citations may be sent to your chosen provider. This handoff gives the agent researcher-curated context; it does not mean the model reverified the sources.

Historical sessions without a domain marker retain their neuroscience interpretation. Start a new session for education research. The domain is fixed when a session is created.

## Analyze and report

Under **Table data analysis**, upload a local CSV version for a registered dataset source. Accept the current plan before saving cleaning rules and running descriptive statistics. The page shows column profiles and summaries rather than copying raw rows into the display; the original CSV stays local. Version and status checks help reproducibility, but means and standard deviations alone do not establish causation or statistical significance.

Link claims to evidence, analysis, or execution records and specify whether they support, challenge, or limit a claim. Reports save immutable versions from accepted claims. When a source, plan, analysis, or execution record changes, review the **Needs review** status before accepting a revised version.

## Optional legacy data catalog and local paper index

In a local installation, **Plugins → Datasets** still mostly lists BrainPilot's neuroscience datasets. It is optional and is not automatically loaded into education sessions. **Plugins → Knowledge Base → My knowledge base / Add papers** opens the local paper-index workflow; education sessions do not call the original local neuroscience knowledge-search tools by default. Education publications can first be registered, checked, and cited in Research projects. See [Skills and Knowledge Base](./skills-knowledge-base) for the resource boundaries.

If you do need data from the original catalog, **Use in new research** adds a downloaded path to a draft. Review the domain, path, provider, model, and expected output before sending. Starting a draft does not run the model or analysis. Read [Research datasets](./datasets) for access and download requirements.

## Session files and persistent files

Session files live under `<BP_DATA_DIR>/workspaces/<session-id>/`. Reusable inputs live under `<BP_DATA_DIR>/data/` and are presented to the runtime through `/data/…`. In a local draft, the Files panel can show this persistent library before a session has been created. Use `@` to select a file instead of guessing its path.

Opening a downloaded dataset selects its folder in Files. It does not copy the full dataset into every conversation. For remote installations, the files belong to the server's data directory.

## Inspect the result

Open **Trace**, select a step, and use a file action to open the associated output in Files. This connects the recorded action to its saved artifact. Internal recovery checkpoints are kept separate from the user artifact count.

Check that the file contains the expected output and that reported numbers match it. A recorded action, a completed task, or a downloadable result is not scientific approval. If a file has been moved or removed since the Trace event, recover it from your retained files or rerun the necessary step; the event itself is not a replacement for the artifact.

## Stop and return later

Use **Stop** to interrupt the current model/tool work. Wait for cancellation to settle before sending a revised request. Reopen the conversation to inspect its saved history and files; retain the same BrainPilot data directory across restarts and upgrades.

Dataset category, search, filters, detail selection, and scope are stored in the page URL so refresh and browser Back/Forward can return to the same view. Compare selections and temporary credentials are not a saved analysis configuration.

## Local and Cloud availability

The local dataset downloader and local knowledge-base setup require backend filesystem and tool access. Upstream hosted Cloud does not contain this fork's education changes and hides these local management controls. This source edition's research workspace is designed for one local user and has no account login or multi-user permission separation. Do not expose it as a shared service for sensitive student records.
